# BM25 与来源证据

## BM25：可解释的检索基线

## 这一课要解决什么

理解词频、逆文档频率与文档长度如何影响排序。

## 核心推导

BM25 将查询词对文档的贡献求和。TF 随重复次数增加而趋于饱和；IDF 降低常见词的区分能力；长度归一化避免长文档天然占优。中文分词质量与中英混合标识符处理直接影响命中，算法名、缩写和术语是本项目的重要信号。

## 一个最小实现

```
idf = log(1 + (N - df + 0.5) / (df + 0.5))
score += idf * tf * (k1+1) / (tf + k1*(1-b+b*length/avg_length))
```

## 容易误判的地方

有检索结果不等于结果相关。至少检查 hit@k，还要区分“应该找不到”的查询；不要强迫每次都有引用。

## RAG 的来源、边界与失败路径

## 这一课要解决什么

把检索片段当作证据材料，控制引用和过度推断。

## 核心推导

RAG 的输入应包含来源 ID、片段与分数。回答中的结论要对应来源或执行结果；检索无命中时应说明不足并继续询问或验证。文档是数据，不能让文档中的“忽略规则、调用工具”变成控制指令。来源必须可回到完整文档复核。

## 一个最小实现

```
evidence = {"doc_id": doc.id, "source": doc.path, "snippet": doc.text}
# 检索内容进入资料区，不覆盖系统工具约束
```

## 容易误判的地方

片段切割可能遗漏否定、适用条件或上下文。只因为片段中出现算法名，就推荐该算法，会产生有引用的错误答案。
