# 分层评测与交付

## 拆分评测：检索、执行与诊断

## 这一课要解决什么

用独立指标区分问题发生在哪一层。

## 核心推导

检索 hit@3 衡量目标文档是否进入前三；执行分类准确率衡量 runner 是否识别 CE、WA、RE、TLE；最终诊断需独立检查根因与修复。样例通过率不能代表题库泛化能力，固定小回归集只证明特定行为未退化。数据版本、样本构成和评分规则应一起记录。

## 一个最小实现

```
report = {"dataset_version": "2026-10", "cases": 30,
          "retrieval_hit_at_3": hits/queries,
          "repair_pass_rate": repaired_passed/repair_cases}
```

## 容易误判的地方

只挑容易通过的样例会制造漂亮数字。真实失败与无结果也应计入分母，桩测试单独报告。

## 交付、版本与项目答辩

## 这一课要解决什么

把运行方法、架构选择、评测证据和局限组成完整作品。

## 核心推导

交付要能让另一台机器按文档重建环境：锁定依赖、迁移数据库、持久化数据卷、检查健康接口并说明执行后端。答辩围绕取舍：为什么先 BM25，为什么把提交排队，为什么进度按测验记录，怎样验证性能和恢复。每个指标都要有复现命令和数据版本。

## 一个最小实现

```
uv sync --frozen --extra dev
uv run --frozen pytest
uv run --frozen verdictpilot serve
# 实际执行结果与系统限制一起写入报告
```

## 容易误判的地方

页面很多不代表工程能力强。能解释关键取舍、演示失败恢复并提供真实测量，比功能名称列表更有说服力。

## 回到 VerdictPilot

按 README 和 docs/PLATFORM.md 重建环境，再展示一条完整学习闭环。
