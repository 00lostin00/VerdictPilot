# 威胁模型

## 受保护对象

- 宿主机文件、网络凭据和 Docker daemon。
- API Key、用户代码、题面与错题记录。
- 服务可用性和模型调用预算。

## 主要风险

1. 用户代码读取宿主机文件、联网或启动大量进程。
2. 无限循环、超大输出和编译炸弹耗尽资源。
3. Prompt injection 诱导 Agent 绕过工具规则或伪造执行结果。
4. Trace 意外记录密钥或敏感源代码。

## 已有控制

- 默认关闭执行；本地后端需要双重显式开关。
- Docker 后端不挂载项目目录或 Docker socket，只读挂载一次性提交目录。
- 容器禁网、非 root、只读根文件系统，并限制 CPU、内存、进程、文件和输出。
- 最终回答规则明确区分“样例通过”和“OJ AC”。
- API Key 只从环境变量读取，示例文件不含真实密钥。
- v0.2 对代码、题面、测试输入与输出设置大小约束；提交最多 16 个在途任务、两个 worker，诊断同时最多四个，过载返回 429。
- 本地 runner 在读取 stdout/stderr 时限制各自缓存，默认各 64 KiB；超时或输出超限会结束进程树。它没有宿主机文件、网络或内存隔离。
- 学习记录按本地标识筛选，运行和错题操作检查归属；知识正文通过已入库 ID 查询，不接受任意文件路径。归属筛选不等于鉴权。

## 尚未解决

- Docker 共享宿主机内核，不等于强隔离；生产环境应考虑 gVisor、Firecracker 或独立判题节点。
- 当前没有登录认证、基于身份的授权、按来源的速率限制和内容保留策略，不能直接公网部署。有界任务容量只提供背压。
- Docker runner 的管道输出仍在执行结束后截断，内存主要依赖容器总限额；本次没有验证 Docker 隔离。生产执行还需独立 judge、取消与容器生命周期清理。
- 浏览器 localStorage 保存学习标识和草稿，导出文件包含代码与笔记；清除站点数据前应先导出并记录标识。
- 本地 JSONL trace 仍可能含题目片段；生产环境需脱敏、访问控制和过期清理。
