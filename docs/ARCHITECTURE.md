# 架构说明

## v0.2 学习平台

课程、题库、项目工坊与用户记录围绕原有诊断内核扩展。`catalog.py` 读取版本化内容并负责服务端评分；`platform_api.py` 提供平台接口；`platform_store.py` 持久化进度、草稿、运行、复习和项目证据；`platform_service.py` 负责有界的后台提交队列。前端为 `web/index.html`、`web/app.js` 与 `web/styles.css`，无需前端构建。

SQLite 使用 WAL、短事务和显式关闭连接。提交队列有两个 worker、16 个在途容量；诊断同时最多四个，过载时返回重试提示。服务器启动会将遗留任务标记为中断。离线诊断在工作线程执行，避免编译与子进程阻塞 ASGI 事件循环。本地子进程输出在读取过程中限制缓存，超时和输出超限会清理进程树。

这是单实例本地平台，学习标识并非认证凭据。当前进程内任务不会在重启后续跑。表结构、接口、状态机、学习路线和部署资源说明见 [PLATFORM.md](PLATFORM.md)。

## 两条运行路径

`offline` 路径按固定顺序调用知识检索、错题读取和可选 C++ runner，适合单元测试和无 Key 演示。规则与工具顺序确定；运行 ID、耗时、个人历史和实际执行输出随请求变化。

`openai` 路径把同样的能力注册为 Agents SDK 函数工具，由模型根据题面、模式和工具结果决定调用顺序。SDK tracing 用于观察模型调用、工具调用和失败路径，本地同时写入 JSONL 事件，便于离线复盘。

## 数据边界

- `knowledge_documents`：自有 Markdown 算法笔记及来源。
- `mistakes`：只有执行结果或用户确认后的错误才允许写入。
- `traces.jsonl`：记录工具名、状态和文档 ID，不主动记录 API Key。

## 为什么不用大型向量库

当前知识规模较小，自写 tokenizer + BM25 可以建立可解释基线。检索项目要求先建立查询集、固定数据划分和逐查询报告，再比较分块、向量召回或 rerank 的效果与成本。
